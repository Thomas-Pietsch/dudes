# IDE run sheet

One run of the starter in a fresh product repo, in [Cursor](CURSOR_SETUP.md) or [Cline](CLINE_SETUP.md). The starter was run on Claude Code only. This sheet is what to do at each step and what to note, so a run that goes differently leaves a finding and not a guess. It does not repeat the guides: setup and fixes are there, the flow's pictures are in [the walkthrough](WALKTHROUGH.md).

Before you start: git, make, a POSIX shell (on Windows: Git Bash), a model in the host, an empty folder. Note the host and its version, the model, and your OS. A hosted model receives your code and your specs: use the sample idea below, nothing private.

| # | Do | Expect | Note |
|---|---|---|---|
| 1 | In the empty folder: `git init -b development`, add the submodule, copy `AGENTS.md`, `Makefile` and `CLAUDE.md` from `templates/product`, ignore `SESSION_STATE.md`, `git config core.hooksPath .dudes-framework/hooks`, commit `chore: DUDES starter [🔹human]` ([walkthrough, step 0](WALKTHROUGH.md#0-set-up-the-repo)) | The commit goes through: it has a tag | Any command that failed. `CLAUDE.md` is harmless here |
| 2 | Open the folder: Cursor, File, Open Folder; Cline, Rules panel. Start a new Agent chat (Cursor) or a new task in **Act** mode (Cline) | Cline lists `AGENTS.md`, on. Cursor shows no list: step 3 is its check | Is the clone's own `AGENTS.md` listed too? Any prompt about files outside the workspace |
| 3 | Ask: `As PM & Software Architect: which files do you read before you write a spec?` | First line `## 🔷 PM & Software Architect`, then `Active rules: … · Toggles: …`, then `Flow:`. The rules and `AGENTS.md` loaded without you pointing at them | The header's place (first line, or after the reads). Missing toggles line. Speaks as DevOps: the clone's `AGENTS.md` applied |
| 4 | By hand, in a terminal: `git commit --allow-empty -m "chore: no tag"`, then the same with `[🔹human]` | The first is refused: `❌ DUDES §13: Missing role tag`. The second passes | Whether the host's own commit button shows the refusal. Later: what the agent does when its own commit is refused |
| 5 | New chat. Send the idea of [walkthrough step 1](WALKTHROUGH.md#1-the-idea) | The PM writes `spec/` and commits it with `[🔹PM & Software Architect]`, then `→ Handing off to **QA Engineer (Author)** — proceeding now.` A role hands over without you | Every stop where you had to act: command approvals, a tool-call limit, `continue`. The Run Mode or auto-approve setting you used. A role that was skipped |
| 6 | Read `git log --oneline --all --decorate` and run `make check` | Next two commits: `test(…) [🔹QA Engineer]`, then `feat(…) [🔹Developer]`. Tests were written first and `make check` is green now | Order of commits. A test file changed in the Developer's commit. `TEST`, `FMT` and `LINT` set in the `Makefile` |
| 7 | QA (Verify) has run: `git branch`, then `git show release/<product>-v0.1 --stat` | A `release/bookshelf-v0.1` branch cut from the verified commit, one QR commit on it, and the demo offer: `Seal it`, `Skip demo` or `Not good enough` | Where the QR went. Nothing sealed yet. Which closing token it used |
| 8 | The one-repo guard, by hand. On `release/bookshelf-v0.1`: `git commit --allow-empty -m "feat(x): y [🔹Developer]"`. Then on `development`: `echo x > spec/X_QR.md && git add spec/X_QR.md && git commit -m "docs(qa): verdict [🔹QA Engineer]"`, and afterwards `git rm -q --cached spec/X_QR.md && rm spec/X_QR.md` | Both refused: `❌ DUDES §12` ([`rules/DUDES.md`](../rules/DUDES.md) §6 *One Repository*, §12). On `release/*` only QA commits, and only the QR; a QR does not go on `development` | The hook finds the one-repo product by the `Repo type` row of `AGENTS.md`. If an agent edited that row, the guard is silent: check the row |
| 9 | New chat: `Seal it` | The PM tags the tip of the release branch (the QR commit) `bookshelf-v0.1.0`, annotated, naming the verified commit. It does not push | `git tag -n` and `git log --all --decorate`. A tag before your word. A push attempt |
| 10 | New chat: `Not good enough: a title of 150 letters é is refused as too long. The limit is 200 characters, not 200 bytes.` | A failing test first, then the fix, then QA (Verify) merges `development` into the release branch and updates the QR in place. The merge commit is not refused by the hook | The order. Whether the state came back from git in a new chat. A refused merge |
| 11 | [Walkthrough step 7](WALKTHROUGH.md#7-check-it-yourself) | The test commit is red, `development` is green, the QR matches | Where the agent's word and your check differ |

## Where a finding goes

Open an issue on the repo, with the [bug form](https://github.com/Thomas-Pietsch/dudes/issues/new/choose). Choose *Which way in?*: IDE agent with the rule files. Give the host and version, the model, your OS, the step number from this sheet, what you expected and what you saw. Paste the refusal text or the first lines of the answer. Remove secrets and private code first.
